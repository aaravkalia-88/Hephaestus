# Hephaestus — Product Requirements

Source: [scope: The Unique Kernel and The POC Boundary](scope.md).

## The Core Journey
1. Install the entire Hephaestus skill folder into a supported agent.
2. Ask for an audit or a specific frontend repair in a selected local project.
3. Receive findings with locations, evidence, remedies and regression risks.
4. Repair within the authorized file scope in an isolated checkout.
5. Inspect the diff, repeat relevant behavior and responsive checks, and distinguish verified work from unresolved work.

## Screens and Layout
The product surface is the host agent's conversation, files, diff and local report. A separate project-list screen is synthetic evaluation material, not the Hephaestus product.

## Look and Feel
Apply the learner's frontend policy and preserve explicit project exceptions. For the evaluation, use readable flat surfaces and native controls; retain the synthetic brief's approved brand and project data. No fabricated customers, metrics or product screenshots.

## Features and Behavior

### Scoped audit and repair
Audit-only requests leave target source unchanged. Repairs preserve routes, endpoint contracts and approved content. Unknown business or privacy facts require review; frontend feedback must never invent backend success.

### Observable repair outcome
The runnable fixture must visibly show waiting, success, empty and request failure, with recovery through retry. Malformed responses must not become render errors. Rapid successive requests must not let an older result replace the latest selection. Remote project names render as text.

### Honest evidence
Retain the original input and fresh-agent patch, run actual browser checks at all three widths, inspect captures, and disclose unrun checks. The report helper checks consistency, not truth. Passing helper tests alone is not proof of frontend quality.

## States and Boundaries
- **Runtime available:** inspect actual rendering and interactions.
- **Runtime unavailable:** report skipped browser checks; edits remain unverified.
- **Failed request:** visible recoverable failure; no substituted successful data.
- **Unconfirmed fact:** owner review; no invented claim or unsupported fraud accusation.

## Product Decisions
The learner chose Hephaestus, an installable skill, the supplied frontend rules, Taste investigation, backend deferral, and the Devpost-guided improvement pass. The small fixture's implementation details are agent choices within that authorized scope.

## What We're Building
Keep the existing skill; add a runnable evaluation, targeted instruction improvements supported by observed gaps, technical Devpost documentation and a reusable code map.

## Deferred From the POC
Backend implementation and live-service integration. The local fixture's response service only simulates known test conditions and is explicitly labeled.

## Non-Goals
No hosted app, standalone automated detector for every rule, universal aesthetic score, automatic deployment or AI-written Devpost submission answers.

## Open Questions
The learner's hands-on observations, learning wrap-up and demo are pending. They do not prevent agent verification of the authorized technical work, and cannot be marked complete by it.
